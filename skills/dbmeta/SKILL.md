# 查询数据库表结构

用本机的 `dbmeta-cli` 获取表结构。只要知道 `库.表`,工具会自己找到有这个库的实例。连接信息在当前项目的 `.dbmeta/config.json`,只有 dbmeta-cli 会读它。

## 1. 一条命令取回所有要用的表

先从用户的话、SQL、yml、ORM 模型里收集这次任务要用的全部 `库.表`,再**一次**取回,不要一张一张调用:

```bash
dbmeta-cli table get bdp_ent.dwd_ent_employee bdp_ic_gsxt.tb_company_base
```

- 不用先查实例,不要先运行 `instance list` 或 `db list`。
- 表名来自用户或项目代码,不要猜表名,也不要遍历。库名和表名分开写在 yml 里时(`database` + `tables`),自己拼成 `库.表`。
- stdout 只有表结构(Markdown),来源和警告在 stderr。
- 命中缓存时不联网、不用密码,所以重复调用是便宜的。

### 一个库在多个实例里

同名库出现在多个实例(例如测试和生产)时,工具会逐个实例取,有这张表的都输出,每份前面有一行 `<!-- 库.表 @ 实例 -->`。结构相同的只完整输出一份,其余写"结构与 xxx 相同"。

- 结构相同:用哪个都行。
- 结构不同:按用户的上下文选(要对哪个环境写 SQL?),并在回复里说明用的是哪个实例。拿不准就问用户,不要自己挑。
- 只想看某个实例:加 `-i <实例>`,例如 `dbmeta-cli table get -i prod bdp_ent.t1`。

### 表很宽、或需要结构化数据

- `--print-path` 每行输出一个缓存文件路径,再用 Read 工具读文件。路径以命令输出为准,不要靠 glob 或搜索去找。
- `--format json`:只有一个结果时是对象,多个结果时是数组。

## 2. 缓存规则

| 场景 | 参数 |
|---|---|
| 日常理解表结构 | 默认。缓存在有效期内(默认 7 天)直接读缓存,过期才查库 |
| 用户说"刚改了表"、"迁移后",或 SQL 报 `Unknown column`、`doesn't exist` | `--refresh` 强制查库 |
| 没有密码、离线、或查库失败 | `--cached` 只读缓存,不联网 |

stderr 里出现 `stale` 警告,说明返回的是过期缓存,要告诉用户数据可能不是最新的。出现"表结构已变化"时,提醒用户表刚被改过。某个实例"已跳过"只是说那个实例没有这张表或连不上,别的实例有结果就够了。

## 3. 找不到库(退出码 2,提示"库 xxx 没有出现在任何实例里")

工具已经自动同步过一次实例的库名。再按下面处理,最多一次:

1. 先确认库名是不是写错了(对照项目代码)。
2. 如果用户刚新增了实例,运行 `dbmeta-cli db sync`(同步全部实例的库名),然后重试原命令。
3. 仍然不行:告诉用户这个库不在已登记的实例里,请他确认实例是否已登记并填好密码。不要猜相似的库名。

只有用户问"某个库在哪个实例"时才用 `dbmeta-cli db list [--db 库]`,它只读本地文件,不联网。

## 4. 登记新实例

```bash
dbmeta-cli instance add <名称> --jdbc "<jdbc 链接>" --env <prod|test|...> --desc "<说明>"
```

- 如果 JDBC 链接里带了密码,先把密码去掉再传入,也不要在对话里复述密码。
- 完成后告诉用户:去 `.dbmeta/config.json` 里自己填写 `password`,填好后运行 `dbmeta-cli db sync <名称>` 登记这个实例里的库。
- `.dbmeta/` 不存在时会自动创建。也可以让用户先运行 `dbmeta-cli init`。
- 如需限制可访问的库,加 `--allow-db a,b`。

## 5. 失败时怎么办

部分表取不到时,能取到的照常输出,退出码取最严重的一个。

| 退出码 | 含义 | 处理 |
|---|---|---|
| 2 | 参数、标识符、库、实例或配置错误 | 若提示"未找到 .dbmeta/config.json",让用户运行 `dbmeta-cli init`;"库没有出现在任何实例里"见第 3 节;其余按提示修正 |
| 3 | 密码为空或认证失败 | 让用户自己编辑 `.dbmeta/config.json` 填写密码。不要向用户索要密码 |
| 4 | 表不存在,或账号无权限查看 | 请用户确认库名、表名和权限。不要重试,不要猜相似的表名 |
| 5 | `--cached` 没有缓存 | 去掉 `--cached` 再试,或让用户先配置好密码 |
| 6 | 网络或连接失败 | 改用 `--cached`,并告知用户数据可能已过期 |
| 7 | 库不在 `allow_databases` 白名单内 | 不要重试。请用户确认是否需要放开白名单 |
| 127 / command not found | 未安装 dbmeta-cli | 告诉用户先安装 dbmeta-cli |

## 6. 禁止事项

- 不要用 mysql 客户端、脚本或任何其他方式直连数据库,只能用 `dbmeta-cli`。
- 不要向用户索要数据库密码。
- 不要读取、打印、复述 `.dbmeta/config.json`,里面有密码。`.dbmeta/routes.json` 没有密码,可以直接读。
- 不要批量遍历表,只取当前任务需要的表。
- 不要用旧写法 `table get <实例> <库> <表>`,已经不支持。
